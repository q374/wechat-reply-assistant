# 微信表达助手

面向一对一敏感聊天的 Android AI 回复助手。用户主动打开入口，手动提供对方消息和必要背景，选择回复目标与语气，生成三条可比较、可编辑的候选，然后回到微信检查并手动发送。

> 当前版本是 Android MVP，已完成主流程验证；尚未作为正式应用发布，也未完成真人用户验证。仓库中的评测使用虚构场景和模拟任务，不能视为真人用户数据。

## 产品定位

重要聊天中，用户通常知道自己想表达什么，却需要同时处理背景、关系、语气和分寸。通用 AI 可以生成文字，但用户仍要离开当前聊天、组织提示词、解释上下文，再把结果复制回来。

这个项目把一次回复任务收敛成一条可检查的流程：

```text
主动打开入口
    ↓
选择本机对象，手动粘贴对方消息
    ↓
补充必要背景，选择回复类型和语气
    ↓
生成三条同类型候选
    ↓
编辑、逐条复制
    ↓
回微信检查，由用户手动发送
```

## 产品取舍

- **用户主动提供上下文**：应用不会后台监听或读取全部微信聊天记录。
- **三条候选**：让用户比较不同的表达角度和推进力度。
- **复制后手动发送**：应用不自动写入微信输入框，也不点击发送按钮。
- **先做单次任务闭环**：长期记忆、群聊、批量回复、支付和自动化发送不属于当前 MVP。
- **本机保存敏感配置**：对象档案保存在手机本机；直连模式的 API Key 使用 Android Keystore 加密保存。生成前会说明请求范围，用户确认后才发送到 AI 服务。

## 当前实现

- Android Java 客户端：对象档案、回复/主动开聊模式、回复类型选择、输入校验、加载与失败态、三条候选、编辑和复制。
- AI 调用：支持手机直连 DeepSeek，也保留本地 FastAPI 后端用于开发联调；模型返回必须符合约定 JSON，客户端和后端会校验候选结构。
- 失败边界：输入不足、无效 Key、服务不可用、超时、限流和无效模型返回都会保留用户输入，不展示伪装成真实生成的替代候选。
- 安全边界：不自动读取、不自动写入、不自动发送微信消息。

## 验证状态

已验证：

- 标准签名 `0.3.10` 构建、对齐、签名和 Android 15 安装。
- 虚构内容下的隐私确认、中文输入、真实三条候选、候选编辑复制和复制后回微信手动粘贴。
- 无效 Key、服务失败、候选数量/类型异常等失败边界。
- 30 条虚构场景的 AI 质量评测和 6 类模拟用户评测。

- 更长中文消息、真实断网和部分语义级事实边界。
- 当前最新视觉提交的标准 release 重新构建，受本机 `aapt2` 环境问题影响。

## 代码结构

```text
reply-assistant/       Android 产品代码和 Windows 构建脚本
backend/               可选的 FastAPI 本地联调服务
docs/                  产品、技术、评测和开发说明
PRD.md                 产品定义、范围和隐私边界
```

本仓库不提交 Android SDK、IDE、构建产物、截图/XML、视频工程依赖、本机配置、日志或密钥。它们仅用于本地开发，并由 `.gitignore` 排除。

## 本地运行

Android 客户端的构建和安装步骤见[安装说明](docs/INSTALL.md)。构建脚本使用本机 Android SDK 和 JDK；release 签名材料只从本机被忽略的 `.secrets/` 读取，不随仓库提供。手机直连模式需要在应用设置中配置 DeepSeek API Key；调用真实模型可能产生费用。

本地 FastAPI 后端是历史联调路径，不是当前手机直连主路径。启动方式见[后端说明](backend/README.md)。

## 隐私与使用边界

应用只在用户点击生成并确认后提交当前任务所需内容。对象档案和 Key 的本机保存不代表 AI 服务看不到请求内容；实际发送范围取决于用户确认的输入。演示请使用虚构内容，不要把真实聊天、密钥或个人信息放进公开 issue、截图或日志。
