# 30 条虚构场景 AI 输出质量评测

更新时间：2026-10-11

## 口径与方法

本轮使用 30 条虚构的一对一聊天场景，调用当前手机直连路径使用的 DeepSeek 模型、系统提示词、JSON 约束和 `max_tokens=1024` 配置。对象名、消息、档案均为虚构；没有读取或发送真实微信内容。先记录 0.3.9 基线，再对 0.3.10 修复重跑。原始请求和模型返回只保留在本地评测目录，不进入公开仓库。

每条输出按 1～5 分人工复核：事实准确、语气匹配、具体性、可接话性、候选差异、不编造事实。原始输入和模型返回只保留在本地评测目录；公开仓库只保留可复核的方法、摘要和失败案例。评测结果是模型评测，不是真人偏好数据。

## 结果摘要

- 0.3.9 基线：30/30 个唯一场景最终得到三条非空候选，六项平均分为 4.46/5；候选差异平均 3.70，不编造事实平均 4.77。
- 0.3.10 修复后：30/30 个唯一场景最终通过客户端同类型和 JSON 结构校验；R10 的一次四条候选被安全拒绝并重试成功，模型夹带说明文字也可被安全提取为 JSON。
- 修复后抽查显示 R17/R18 已从直接编造经历改成带条件的轻松回应；R22 仍有“我一般会……”式个人经验暗示，保留为下一轮 P1。
- 结果证明提示词能改善边界，但不能单独保证所有输出不编造，后续仍需要语义级事实检查或更强的评测集。

## P1 行动

- 在提示词和客户端校验中强化 `route=general`：不得把“喜欢、去过、做过、看过、熬过”等个人事实写成既定事实；不确定时改用假设问法。
- 增加模型输出的 JSON 解析兜底和可观测记录；解析失败时继续不展示候选，提示用户重试。
- 为高敏感/医疗情绪场景增加“尊重空间、避免代入式经历、避免承诺结果”的评测规则。
- 增加候选差异标准：三条候选必须在开场方式、问题角度或推进力度上至少有一项明显不同。
